# Source Trust Rules

- Prefer current repository source, approved requirements, confirmed environment, ADRs, and selected provider profiles in that order.
- Treat supplied practice guides and long reference documents as conceptual source notes, not copy-ready implementation authority.
- Verify volatile FiveM natives, manifest directives, provider APIs, library versions, and tool behavior against current official primary documentation when they affect implementation.
- Record only the normalized decision or compact provider operation; do not copy whole external documents into default AI context.
- When sources conflict, preserve approved product behavior and report the conflict instead of silently choosing an example.
- Mark runtime behavior as unverified until exercised on the required FXServer, CEF, provider, or database environment.
