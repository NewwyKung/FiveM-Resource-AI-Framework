# Requirements Discovery Checklist

Before implementation of a new resource, major feature, or ambiguous change:

- [ ] User problem and desired outcome are clear.
- [ ] Included scope, excluded scope, and minimum useful version are defined.
- [ ] Primary, alternate, cancellation, and failure flows are defined.
- [ ] Permissions, roles, jobs, locations, costs, limits, and prerequisites are defined.
- [ ] Client, server, shared, config, UI, and database ownership are explicit.
- [ ] Server authority and validation rules are explicit.
- [ ] Events, callbacks, exports, commands, state bags, and error contracts are identified.
- [ ] Configurable values and config file locations are identified.
- [ ] Persistence, transactions, audit, disconnect, restart, timeout, and cleanup behavior are defined.
- [ ] UI requirement is resolved; UI work has an approved wireframe before visual design or implementation.
- [ ] Localization, assets, performance, accessibility, and expected scale are considered.
- [ ] Acceptance criteria and validation evidence are measurable.
- [ ] Recommended defaults and rejected alternatives are recorded.
- [ ] Requirements are stored in `.ai/memory/requirements/`.
- [ ] Feature registry is created or updated.
- [ ] User approved the brief or explicitly authorized recommended defaults.
