# Security Policy

Please do not publish secrets, webhook URLs, API keys, database credentials, private provider documentation, or exploitable vulnerability details in a public issue.

For a suspected vulnerability, contact the repository owner privately through an available GitHub profile contact method. Include the affected version, reproduction steps, impact, and a minimal proof of concept.

Security-sensitive changes should preserve server authority, validate untrusted input, rate-limit externally triggerable operations, avoid logging credentials, and pass the release secret scan.

This hobby project is provided without a guaranteed response time or security support window. Reports will be reviewed when possible.
